# Social Network Data Processing & Recommendation Engine

A Python-based social network data pipeline and recommendation prototype built using Jupyter Notebooks and JSON datasets. This project demonstrates how to ingest social graph data, clean noisy records, and generate **"People You May Know"** and **"Pages You Might Like"** recommendations.

---

## Project Overview

Social media platforms rely on graph relationships (friendships and user-page interactions) to suggest relevant connections and communities. In this project, social network data is modeled in JSON format and processed across four modular Jupyter Notebooks:

1. **Data Ingestion & Display** (`basic_Read_write.ipynb`) – Reads JSON datasets and displays users, their connections, and available pages.
2. **Data Cleaning Pipeline** (`data_cleaning.ipynb`) – Filters invalid records, deduplicates friend lists and pages, removes inactive users, and outputs clean JSON data.
3. **Friend Recommendation Engine** (`people_you_may_know.ipynb`) – Suggests second-degree connections ranked by mutual friend count.
4. **Page Recommendation Engine** (`pages_you_might_like.ipynb`) – Recommends unliked pages based on shared page interests with other users.

## Features & How It Works

### 1. Data Loading & Display (`basic_Read_write.ipynb`)
* Parses JSON files using Python's built-in `json` module.
* Iterates through `users` and `pages` to display user IDs, names, friend lists, liked pages, and page titles.

### 2. Data Cleaning (`data_cleaning.ipynb`)
Transforms raw/noisy datasets (such as `data2.json`) into clean, reliable data (`cleaned_codebook_data.json`) through four steps:
* **Missing Name Removal:** Filters out users whose `name` field is empty or contains only whitespace.
* **Friend Deduplication:** Removes duplicate friend IDs using Python `set` conversion.
* **Inactive User Pruning:** Removes users who have neither friends nor liked pages.
* **Page Deduplication:** Deduplicates pages by `id` so each page ID maps to a single record.

### 3. People You May Know (`people_you_may_know.ipynb`)
* Maps each user ID to a `set` of direct friends for $O(1)$ membership lookups.
* Traverses friends-of-friends (2nd-degree connections) for a given `user_id`.
* Excludes the user themselves and existing direct friends.
* Ranks candidate user IDs in descending order based on the number of mutual friends.

**Example Output (on `massive_data.json` for User ID `1`):**
```text
People You May Know for User 1: [7, 8, 9, 10, 11, 12]
```

### 4. Pages You Might Like (`pages_you_might_like.ipynb`)
* Maps each user ID to a `set` of their `liked_pages`.
* Computes interest overlap (`shared_pages`) between the target user and every other user via set intersection.
* Scores unliked pages by accumulating the count of shared pages from users who liked them, then returns page IDs sorted by relevance score.

**Example Output (on `massive_data.json` for User ID `1`):**
```text
Pages You Might Like for User 1: [103, 105, 107, 104, 106, 108, 109, 110, 111, 112, 113, 114, 115, 116, 117, 118, 119, 120, 121, 122, 123, 124, 125, 126, 127]
```

## Getting Started

### Prerequisites
* **Python 3.8+**
* **Jupyter Notebook** or **JupyterLab** (or VS Code with the Jupyter extension)
* No external third-party libraries required (uses Python's standard `json` module).

### Running the Project
1. **Clone the repository:**
   ```bash
   git clone https://github.com/<your-username>/<your-repo-name>.git
   cd <your-repo-name>
   ```
2. **Launch Jupyter Notebook:**
   ```bash
   jupyter notebook
   ```
3. **Run the notebooks in order:**
   * Open `basic_Read_write.ipynb` to inspect the sample data.
   * Open `data_cleaning.ipynb` to see how messy records are sanitized and saved.
   * Open `people_you_may_know.ipynb` and `pages_you_might_like.ipynb` to generate recommendations for any `user_id`.

## Future Improvements

* **Database Integration:** Migrate from flat JSON files to PostgreSQL or a graph database (e.g., Neo4j) for indexed lookups at scale.
* **Top-K & Threshold Filtering:** Return top-$K$ results with readable user/page names alongside IDs, and filter out zero-overlap page suggestions.
* **Caching & Precomputation:** Use Redis or scheduled batch jobs to precompute recommendations for high-traffic users.
* **CLI / REST API:** Package the recommendation functions into a FastAPI or Flask service.
